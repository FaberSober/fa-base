# ADR-007：部门管理页面优化

- 状态：Accepted
- 日期：2026-09-19
- 范围：部门管理页面、部门编辑弹窗、部门树查询与部门操作安全
- 关联页面：`/admin/system/hr/department`
- 兼容页面：`/admin/system/hr/user`

## 1. 背景

当前部门页面使用 Ant Design `Table` 渲染树形数据，查询、展开、行操作和编辑弹窗均可用，但存在以下问题：

- 前端使用 `sortId`，后端部门实体字段为 `sort`，排序列契约不一致。
- 树接口返回基础部门实体，页面按 `DepartmentVo` 读取负责人，负责人姓名无法稳定展示。
- 编辑弹窗初始化了 `type`，但没有类型表单项，新增和编辑无法维护部门类型。
- 查询后默认展开全部节点，搜索时没有稳定保留命中节点的祖先路径。
- 删除会由树基类级联删除子树，当前后端只检查当前部门员工，存在误删风险。
- 编辑父级只阻止选择自身，没有阻止选择后代，存在形成循环树的风险。
- 部门弹窗位于用户页面目录下，部门页面通过相对路径反向引用，模块职责不清晰。

## 2. 决策

采用“结构化树表工作台 + 分层编辑表单”的方案：

1. 保留现有部门树、`moveUp`、`moveDown`、新增、编辑和删除能力，不引入组织架构图作为主视图。
2. 页面采用部门专用树表和顶部工具栏，复用现有菜单管理页面的层级、主题和操作菜单样式。
3. 树查询返回部门管理所需的负责人信息；优先增加部门域的管理树查询能力，不修改公共 `BaseTree` 的泛型契约。
4. 前端使用完整树数据进行保留祖先的本地筛选；数据量明显增大时，再切换为后端返回命中路径的查询方式。
5. 编辑表单增加必填部门类型，暂不强制“公司 → 部门 → 小组”的层级关系；父级选择必须禁用当前节点及其后代。
6. 删除默认禁止非叶子部门，以及子树中仍有员工的部门；前后端均执行校验，避免只依赖前端提示。
7. 部门弹窗移动到部门域或共享部门组件，并保持用户部门管理页面的调用兼容。

## 4. 开发说明

### 4.1 部门树数据和查询

- 新增或扩展部门管理树查询，返回 `DepartmentVo` 所需的负责人信息。
- 前端一次获取完整树数据，在页面内按名称、类型和负责人筛选，并保留命中节点的祖先。
- 搜索时自动展开命中路径；清除搜索后恢复用户此前的展开状态。
- 刷新、保存、移动和删除成功后重新加载树，同时尽量保留当前筛选条件和展开状态。
- 如果后续部门数量超出一次性加载的合理范围，再增加服务端的命中路径查询，不在本次改造公共树组件。

### 4.2 树形表格和工具栏

- 首列展示树缩进和轻量层级标记，避免仅依靠缩进区分层级。
- 类型使用带文字的语义标签；空负责人显示“未设置负责人”，空描述显示“—”。
- 保留排序字段，并通过“上移 / 下移”维护同级顺序。
- 顶部统一放置搜索、筛选、命中数量、刷新、展开全部、折叠全部和新增部门。
- 操作列保留编辑、新增子部门两个高频入口，其余操作收进“更多”菜单。
- 长名称和描述省略显示，悬停时展示完整内容；删除入口使用危险样式并与普通操作分隔。

### 4.3 部门编辑表单

- 部门弹窗移动到 `department/modal` 或共享部门组件目录，保持 `/user` 页面的现有调用方式。
- 新增“类型”必填字段；暂不根据类型限制父级层级，避免在业务规则未确认前阻塞录入。
- 编辑时计算当前节点的后代 ID，并传给级联选择器禁用；后端再次验证，不能只依赖前端隐藏选项。
- 上级部门、名称、类型、负责人使用两列布局，描述使用整行文本域。
- 负责人继续使用 `UserSearchSelect`，筛选器和编辑表单保持同一套用户选择语义。
- 表单保存成功后关闭弹窗、提示结果并刷新树；请求期间锁定提交按钮。

### 4.4 删除和移动安全

- 默认只允许删除没有子部门且子树内没有员工的节点。
- 删除前显示部门名称；若后端返回阻止原因，直接展示原因，不覆盖当前树状态。
- 移动操作沿用现有 `moveUp`、`moveDown` 接口，显示请求中的状态并在完成后刷新排序。
- 后端删除校验必须覆盖待删除节点的完整子树，不能只统计根部门的员工。
- 后端更新父级时校验目标父级不是当前节点或其后代，防止生成循环树。

### 4.5 主题、响应式和可访问性

- 使用现有 `--fa-bg-color`、`--fa-bg-color2`、`--fa-border-color`、`--fa-subtitle-color` 和 Ant Design token。
- 同时验证亮色和暗色主题的正文、标签、边框、悬停、禁用和危险状态对比度。
- 操作按钮具有明确文本或 `aria-label`，支持键盘焦点和禁用状态。
- 处理空树、加载中、请求失败、无搜索结果、长部门名称和窄屏横向滚动。

## 5. 影响与风险

### 正面影响

- 组织层级、负责人和部门类型的含义更清晰，搜索结果不再丢失上下文。
- 高频操作更集中，减少每行堆叠大量链接造成的视觉噪声。
- 删除和换父级增加后端保护，降低组织数据损坏风险。
- 复用现有主题和页面模式，不新增前端依赖。

### 负面影响

- 部门树查询需要返回负责人信息，后端响应模型和接口测试需要同步调整。
- 默认禁止非叶子删除后，管理员需要先处理子部门或员工归属。
- 完整树本地筛选更适合中小规模组织；超大组织需要后续增加路径查询。

## 6. 备选方案

### 6.1 左树右详情

适合查看成员和部门详情，但需要维护选中节点、详情加载、筛选和路由状态，首版不采用。

### 6.2 组织架构图或卡片视图

更适合展示汇报关系，不适合排序、筛选和密集维护，留作独立展示场景评估。

### 6.3 仅调整颜色和间距

无法解决排序字段、负责人数据、类型缺失和级联删除风险，不作为独立方案。

## 7. 非目标

- 本 ADR 不强制实现“公司 → 部门 → 小组”的三级层级规则。
- 本 ADR 不新增批量移动、批量删除、组织导入导出和审计回滚。
- 本 ADR 不重写公共 `BaseTree`，除非页面级实现无法满足现有能力并经过单独评估。
- 本 ADR 不对 `/admin/system/hr/user` 做整体页面重构，仅保持共享部门弹窗兼容。

## 8. 验收标准

- 排序列能正确显示后端 `sort`，移动后同级顺序正确。
- 树表支持名称、类型和负责人筛选，命中子部门时祖先路径仍可见。
- 默认不会因刷新或查询强制展开全部节点，展开和折叠操作状态明确。
- 类型、负责人、父级和描述均能在新增/编辑弹窗中正确读取和保存。
- 当前节点及其后代不能被选为新的父级；后端循环校验能够拦截非法请求。
- 非叶子部门或子树内有员工时不能删除，并能展示明确原因。
- 新增、编辑、移动、删除的加载、成功和失败状态清晰可见。
- 亮色、暗色、空数据、无结果、长文本和窄屏场景可正常使用。
- 完成受影响前端文件的格式检查、局部类型检查和关键交互验证。

## 9. 实施顺序

1. 对齐部门类型、排序字段和管理树返回模型。
2. 增加后端父级循环校验和安全删除校验。
3. 抽离共享部门弹窗，并补齐类型、父级禁用和表单布局。
4. 改造部门页面工具栏、树表列和操作菜单。
5. 接入本地树筛选、命中路径展开和展开状态保留。
6. 补齐暗色、响应式、可访问性和异常状态。
7. 完成局部格式检查、类型检查和页面回归验证。
