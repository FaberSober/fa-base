# ADR-008：后台首页工作台可维护性治理

- 状态：Proposed
- 日期：2026-09-20
- 范围：前端 `/admin/home/desktop` 工作台、布局配置、工作台 Cube 与相关生命周期
- 目标：在不替换现有布局方案的前提下，修复配置一致性、导入安全性和运行时恢复问题

## 1. 背景

工作台由页面、布局配置 Hook、`FaGridLayout` 和 `react-grid-layout` 组成，布局通过 `HOME_LAYOUT / LAYOUT` 配置保存，并支持全局默认布局、用户布局、增删组件、导入导出和拖拽调整。

当前代码已经具备初始化回调保护和“最新布局优先”的保存队列，但仍存在以下风险：

- 清空用户配置后仍保留旧配置 ID，后续保存可能更新已删除记录。
- 导入 JSON 未做解析和布局结构校验，异常输入可能导致页面报错或污染持久化数据。
- 新增组件的布局计算依赖数组顺序，且固定使用 24 列，可能产生重叠或越界。
- 初始化、保存失败缺少明确的页面恢复入口；部分错误恢复能力已经存在但未接入页面。

## 2. 决策

- 保留现有调用链：工作台页面 → `useGridLayoutConfig` → `FaGridLayout` → `react-grid-layout`。
- 优先在共享布局 Hook 和导入边界修复根因，不在页面层重复保存或新增全局状态。
- 继续使用现有的初始化保护、受控布局回调和最新布局保存队列；新增逻辑不得绕过这些机制。
- 布局格式保持兼容：使用组件 ID `i`、位置和尺寸字段，默认列数继续以当前 24 列为准。
- 真实数据、权限过滤、预警查询语义和隐藏 Tab 轮询策略，在确认业务口径前不擅自扩展 API 或改变展示行为。

## 4. 开发说明

### 4.1 布局持久化与清空

- 修改 `FaGridLayoutUtils.ts` 的清空流程：删除用户配置成功后，同时清空 `configRef`、配置状态和当前布局。
- 重新读取全局配置；无全局配置时使用默认布局。
- 后续布局变化必须走现有 `onLayoutChange` 保存队列，不能在清空按钮中另行发起保存。
- 重点文件：`frontend/apps/admin/features/fa-admin-pages/components/utils/FaGridLayoutUtils.ts`。

### 4.2 导入校验

- 在 `ExportAndImportBtn.tsx` 或页面导入入口捕获 JSON 解析异常，失败时只提示用户，不更新布局和服务端配置。
- 校验顶层数组、`i/x/y/w/h` 字段、唯一组件 ID、已注册 Cube、非负坐标和 24 列边界。
- 校验通过后仍统一调用现有布局回调，避免产生第二套保存路径。
- 重点文件：`ExportAndImportBtn.tsx`、`FaInputEditModal.tsx`、`pages/admin/home/desktop/index.tsx`。

### 4.3 新增布局计算

- 修改 `calAddLayout`，不要把当前数组顺序当作二维布局顺序。
- 在现有布局约束内选择首个可用位置，并保证 `i` 唯一、宽度不超过 24 列。
- 优先复用当前布局工具和 `react-grid-layout` 的约束，不引入新的布局库或全局布局状态。

### 4.4 初始化、保存与重试

- 页面接入 `useGridLayoutConfig` 已有的 `loading`、失败状态或 `retryLayout` 能力；若现有返回值不足，只做最小补充。
- 初始化失败时显示可重试状态，不把空布局误保存为用户配置。
- 保存失败时保留最后一次待保存布局，重试成功前不丢失用户调整。

### 4.5 组件有效性与权限

- 无权限或已删除 Cube 不从已保存布局中静默删除，保留布局项并显示“组件当前不可用”占位。
- 新增入口继续使用现有权限过滤，只展示当前可用的 Cube，避免复制一套权限判断。
- 后续如需自动清理失效布局项，另行确认数据迁移和用户提示策略。

### 4.6 数据与轮询

- 统计卡片、趋势图、欢迎区目前包含静态演示值；只有确认该页面为生产统计页后，才按现有 service 模式接入真实 API。
- 预警工作台只查询 `deal: false` 的未处理数据，滚动间隔与组件文案统一为 1.5 秒。
- 隐藏 Tab 是否暂停 Cube 轮询需要结合 `TabContentCache` 的产品体验确认，暂不通过卸载组件破坏 Tab 状态。

### 4.7 图表与交互细节

- ECharts 基础组件及同类图表组件在卸载时调用 `dispose`，释放实例和内部监听。
- Cube 选择项使用可聚焦、可键盘触发的语义元素或补齐等价键盘事件。
- 类型收敛以布局入口和 Cube 元数据为优先，不为一次性重构而改动全部 Cube。

## 5. 实施顺序

1. 修复清空后的配置状态和导入校验，先阻断数据一致性风险。
2. 修复新增布局的碰撞与边界问题。
3. 接入初始化、保存失败的恢复与重试反馈。
4. 确认并处理权限、失效组件和预警查询语义。
5. 再评估数据真实化、隐藏 Tab 轮询和类型/无障碍完善。

## 6. 非目标与风险

- 不替换 `react-grid-layout`，不新增全局状态管理，不引入新的布局库。
- 不在本 ADR 中设计新的后端统计或预警 API；接口变更需另行确认契约。
- 导入校验收紧后，历史导出文件可能需要兼容转换；必须保留合法历史布局的导入能力。
- 清理旧默认布局常量前，需要确认是否存在构建脚本、部署配置或外部页面引用。

## 7. 验收标准

- 清空用户配置后，下一次布局变更不会更新已删除的旧配置 ID。
- 非法或不完整导入不会抛出未捕获异常、改变当前布局或发起保存请求。
- 新增组件不与已有组件重叠，不超出 24 列边界。
- 初始化和保存失败有可见反馈，并可通过重试恢复，且不会丢弃最后一次布局。
- 待确认项完成业务核对后，再更新本表的“当前规划”和“进度”，不以推测替代验证。

## 8. 添加组件面板优化方案

### 8.1 目标与原则

- 将“添加组件”抽屉优化为“工作台组件目录”，同时支持查找、筛选、添加和移除。
- 保留当前右侧抽屉和即时保存机制，不新增临时草稿、全局状态或新的后端接口。
- 组件选中状态继续由当前 `layout` 推导，复用 `handleAdd`、`handleDel`、`onLayoutChange` 和现有保存队列。
- 危险操作与组件选择分层，避免误清空布局或误清空全部用户缓存。

### 8.2 界面结构

- 抽屉标题改为“工作台组件”或“组件管理”，显示“已添加 N / 总数 M”。
- 增加本地搜索框，搜索组件标题和描述；增加“全部 / 未添加 / 已添加”筛选。
- 组件卡片显示标题、描述、已添加状态和可选的布局尺寸；已选状态不能只依赖颜色表达。
- 卡片使用语义化可操作元素，支持键盘操作、`aria-pressed` 状态和可见焦点环。
- 无搜索结果时显示可恢复的空状态，不展示空白区域或无意义的“0 条结果”。
- 卡片宽度填满网格单元，移除不必要的 `max-width` 限制；使用主题变量保证暗色主题下的文本、边框和选中状态具有足够对比度。
- 配置操作分为常用操作和高级操作：
  - 常用：清空当前布局、保存为默认布局、导入/导出配置。
  - 高级：编辑 JSON、上传配置、清空全部用户工作台缓存。
- 明确危险操作文案和影响范围；“清空当前布局”和“清空全部用户工作台缓存”均保留确认步骤。
- 在面板底部复用现有保存状态，显示已保存、保存中、保存失败和重试入口。

### 8.3 组件与状态流

- `FaCubeGrid` 负责搜索、筛选、计数、卡片展示和键盘交互，不维护第二份布局状态。
- 工作台、分析页和监控页复用同一个面板容器，页面只传入配置名称、布局、Cube 集合和现有回调。
- 添加组件继续使用 `calAddLayout` 的首个可用位置算法；移除组件只删除对应布局项，不改变其他组件位置。
- 搜索和筛选只改变面板展示，不触发布局保存。
- 权限过滤继续复用 `useAllLayout`，不在面板中复制权限判断。
- 已保存布局中存在无权限或已删除组件时，继续保留占位；如增加清理入口，必须由用户显式触发。

### 8.4 实施分阶段

#### P0：面板体验

- 修改 `components/cube/FaCubeGrid.tsx` 和 `FaCubeGrid.scss`：增加搜索、筛选、计数、空状态、语义化交互、焦点样式和响应式卡片。
- 修改 `pages/admin/home/desktop/index.tsx`、`pages/admin/home/analysis/index.tsx`、`pages/admin/home/monitor/index.tsx`：调整操作分层并传递保存状态。
- 优先复用现有 `useGridLayoutConfig` 返回值，不新增状态管理。

#### P1：结构收敛

- 新增共享面板容器，例如 `components/cube/FaWorkbenchConfigDrawer.tsx`，统一三个页面的抽屉、配置操作、组件目录和保存状态。
- 将 `ExportAndImportBtn` 的编辑、导出和上传操作归入配置菜单，避免与组件卡片并列竞争视觉层级。

#### P2：目录能力

- 当 Cube 数量明显增长后，再补充可选的 `category`、`icon`、`tags` 和尺寸展示。
- 组件数量较少时不引入虚拟列表、拖拽添加、收藏体系或复杂的最近使用逻辑。

### 8.5 开发前验证与验收

- 定向确认 `handleAdd` 和 `handleDel` 的 `setLayout` 是否稳定触发现有 `onLayoutChange` 保存；不得在面板内新增第二条保存路径。
- 确认连续快速添加或移除组件时只保存最终布局，搜索和筛选不会触发保存。
- 验收应覆盖：关键词查找、三种筛选、已选数量、键盘操作、暗色主题对比度、空状态、危险操作确认、保存失败重试和三个页面行为一致。
