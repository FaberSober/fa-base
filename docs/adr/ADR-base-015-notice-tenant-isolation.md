# ADR-015：系统公告租户隔离

- 状态：✅已完成
- 日期：2026-09-30
- 范围：系统公告管理、首页公告、顶部强提醒及新增公告站内信
- 决策：用户已确认每条公告归属一个租户，历史公告暂不分配。

## 实现

- `Notice` 继承 `BaseTnDelEntity`，复用租户填充与 SQL 拦截器。API 的 `tenantId` 为只读，编辑及批量更新不能转移归属。
- MySQL/PostgreSQL 增量版本 1.0.46 新增可空 `tenant_id varchar(32)` 和索引；历史记录保留 NULL，仅超级管理员未选租户时可见。
- 公告新增只向所属租户有效成员发送消息，异步任务复制上下文并在结束后清理；关闭多租户时仍向全体用户发送。
- 表单展示只读所属租户，未选租户时不允许新增；列表显示租户ID和历史未分配标识。
- 首页和顶部强提醒复用公告接口的租户隔离；已有租户切换执行整页刷新，无需增加刷新机制。

## 验证

- 已通过后端模块编译与定向测试（`NoticeBizTest`、`FaTenantInterceptorTest`、`MysqlMetaObjectHandlerTest`），前端 4 个修改文件的 Biome lint 通过。
- 定向检查：公告字段读写契约、可信租户填充、租户 CRUD SQL、消息接收人与异步上下文、关闭多租户的消息行为。
- 开发阶段提供双库升级脚本，未执行真实数据库升级、启动服务或执行浏览器验证。
- 验收范围：两租户下的列表/详情/编辑/删除/批量操作/导出，以及首页/强提醒、超级管理员和历史公告行为。
- 用户于 2026-09-30 确认验证通过。
