## 当前实施方案：字段加密（2026-10-16）

用户已确认替换原整包信封接入方式。下方旧批次与协议说明保留为历史记录；本节及功能 7–10 为当前实施依据。

- 请求体保持业务 JSON：登录 `{username,password:密文字符串}`；Demo `{text:密文字符串,age:18}`，`age` 明文原样往返。后端只解密指定字段，再复用业务校验。
- 字段协议版本 2：密文字符串由三个标准 Base64 片段 `encryptedKey.iv.ciphertextAndTag` 组成；RSA-OAEP SHA-256 / MGF1 SHA-256、AES-256-GCM 保持不变。字段原文 UTF-8 最多 4096 字节，AAD 固定为 `[2,kid,challengeId,purpose,method,path,field]`。
- 元数据位于 `FaCryptoVersion`、`FaCryptoKid`、`FaCryptoChallengeId` Header；关闭防重放时不发送挑战 Header，仍加密并校验完整性。缺失/重复/伪造 Header、跨字段/路由/用途替换均拒绝，不退回明文。
- 前端 `BaseZeroApi` 和公共请求工具接收 `{crypto:{fields:['password']}}`，自动获取准备信息、按 `kid` 缓存公钥、加密字段并合并 Header。挑战每次独立申请，内部请求不递归，先加密再计算现有 `bs` 签名；原对象不变，失败不发送业务请求或自动重放，Loading 覆盖完整流程。
- 准备接口由后端登记的目标策略决定用途、字段及权限：登录准备继续匿名，业务准备保留登录/许可与目标菜单权限。客户端选项不能关闭服务端保护。当前登记两个密码登录和一个单字段 Demo；后续业务集中登记策略并复用通用解密入口。
- Web、App Demo 同步展示业务 JSON、Header 和解密结果，提供原样重放、篡改、等待过期后提交；Demo 的显式准备仅用于展示，正常业务只声明字段。
- 两个 `/loginV2` 切换到字段协议，不同时兼容旧整包请求。旧 `/login`、Token/短信/注册及既有设备信任逻辑保留。后台和新客户端配套升级；本次不实施旧接口下线。
- 公共工具只处理 JSON 顶层字符串字段；不擅自改造上传、流式正文或其他业务接口。未加密字段不受字段密文完整性保护，仍由原业务规则校验。

## 1. 目标与边界

- **主要目标**：新加密接口在 F12 网络面板中的请求体只有加密信封，不包含可直接编辑的 `username`、`password` 等业务字段。直接修改密文、混入明文字段或替换部分字段时拒绝请求，不能通过附加明文覆盖解密结果。
- **内容保护**：客户端整体加密账号、密码等业务数据，后台解密后复用现有业务校验；密文的完整性由认证标签校验。
- **可选防重放**：开启时，同一份受保护请求最多进入业务处理一次；关闭时，原样重放有效密文可以再次进入业务处理，但修改密文仍然失败。
- **跨端统一**：统一算法、编码、数据结构和错误语义；Web 与原生 App 使用各自平台的密码 API，不要求同一份 JS 直接运行于所有原生端。
- **能力边界**：这是提高 F12 直接改包门槛，不是保证客户端不能改数据。用户仍能修改登录表单，或通过调试前端、调用公开加密流程，为新数据生成合法密文。登录密码是否正确及业务权限仍由后台校验；不能用客户端加密代替业务校验。
- 本期不扩展验证码、设备证明或新的防撞库系统。
- 继续要求 HTTPS。应用层加密不替代 TLS，也不改变数据库已有密码校验及存储方式。
- 本期“Web”指现有 React 管理端，“App”指 `mobile-x`，Demo 各一个，并将这两端的密码登录切换到新接口。Portal 网页、Desktop 和旧版客户端继续调用原登录接口，后续再迁移；H5 当前只有登录壳，本期不补真实登录。
- **兼容边界**：原明文登录接口暂时保留原请求、响应及行为，不受新增防重放开关影响。因此新能力只保护新接口，暂不阻止用户主动改用旧接口提交明文。

- `fa-demo`：仅用于演示的受保护业务接口，复用上述能力。
- Web 纯加密工具优先放入现有 `frontend/fa-ui/packages/core`，通过明确出口复用；请求适配留在各客户端，不依赖管理端 UI。
- App 通用加密接口放在 `fa-core-mobile`，原生实现通过 `uni_modules` 适配；Demo 放在 `fa-demo-mobile`。
- 开发时同步调整受影响的类型、包导出与依赖声明、测试、配置示例、路由、菜单和接入文档。

## 3. 推荐协议

采用 **RSA-OAEP + AES-GCM 混合加密**：每次请求随机生成 AES 密钥，以 AES 加密业务 JSON，再用后台公钥加密 AES 密钥。这样既支持密码，也能支持有大小上限的普通 JSON，不受直接 RSA 加密正文的长度限制。

| 项目 | 固定约定 |
| --- | --- |
| 协议版本 | `v=1`，服务端固定允许的算法，不接受客户端任意选择 |
| AES | AES-256-GCM，每请求随机新密钥，12 字节随机 IV、16 字节认证标签 |
| RSA | RSA-2048，OAEP SHA-256，MGF1 SHA-256，空 label；各端显式保持一致 |
| 文本与二进制 | 正文 UTF-8 JSON；二进制标准 Base64，不换行 |
| 公钥格式 | X.509 SubjectPublicKeyInfo，Base64 编码 DER |
| 密钥标识 | `kid` 选择后台已有密钥，未知或已停用标识拒绝 |
| 密文形式 | `ciphertext` 为 AES 密文后拼接 16 字节标签，再 Base64 |
| AAD | UTF-8 编码紧凑 JSON 数组 `[v,kid,challengeId,purpose,method,path]`，固定顺序 |

请求信封只包含 `v`、`kid`、`challengeId`、`purpose`、`encryptedKey`、`iv`、`ciphertext`。关闭防重放时 `challengeId` 固定为 `null`，AAD 对应位置也使用 JSON `null`。HTTP 方法和路径由目标接口确定，后台按实际目标重建 AAD，不相信客户端自报的路由。拒绝不在信封定义内的附加业务字段。

- 登录正文整体加密 `{username,password}`，避免账号与密码可以独立替换。
- 业务用途采用固定白名单，例如 `ADMIN_LOGIN`、`PORTAL_LOGIN`、`CRYPTO_DEMO`；一个用途映射确定的方法、路径和权限要求。
- 登录账号按原业务处理，密码保持原值；不额外 trim、截断或进行 Unicode 归一化。
- Web 使用原生 Web Crypto；Java 使用 JCA；Android、iOS 使用系统密码能力。已有 CryptoJS 工具不承担本协议的 GCM / OAEP 实现，不新增通用加密依赖。
- 开发 App 前先验证 Android / iOS 原生实现对 OAEP 参数、GCM 标签及编码的一致性；不支持时明确阻塞点，不降级为 ECB、固定密钥或明文。

算法依据：[OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)、[W3C Web Cryptography](https://www.w3.org/TR/WebCryptoAPI/)。

## 4. 防重放开关与请求流程

后端配置 `fa.security.crypto.replay.enabled` 的配置类缺省为 `false`；本项目 `application.yml` 当前显式默认开启，可通过 `FA_CRYPTO_REPLAY_ENABLED=false` 关闭。该开关对本期接入的加密接口统一生效，不影响其他未接入接口。

| 后端开关 | 是否加密及校验密文 | 是否申请/存储/消费挑战 | 原样重放有效密文 |
| --- | --- | --- | --- |
| `false` | 是 | 否，不依赖挑战 Redis | 允许再次进入业务处理 |
| `true`（本项目默认） | 是 | 是，默认有效期 120 秒 | 首次消费后拒绝 |

- 开关只配置在后端，随应用配置发布/重启生效，不新增管理页面或热更新机制；多实例保持同一配置。
- 服务端返回当前策略供客户端适配，但最终依据服务端配置执行；客户端传参不能关闭防重放，也不能关闭加密。
- 开关切换期间的旧请求允许明确失败，客户端重新读取准备信息后由用户再次提交，不降级明文、不自动重试业务请求。

拟新增以下接口，实际命名沿用模块规范：

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/base/security/crypto/public-key` | 允许未登录，返回 `v`、`kid`、公钥；不返回私钥 |
| `POST /api/base/security/crypto/prepare` | Demo 专用，要求登录与演示菜单权限；返回当前策略及可选挑战 |
| `POST /api/base/security/crypto/prepare-login` | 登录专用，允许未登录，仅接受两种登录用途；返回 `kid`、`replayEnabled`，开启时返回挑战及到期时间 |
| `POST /api/base/admin/auth/loginV2` | 新增管理端加密登录，允许未登录，仅接收加密信封，对应 `ADMIN_LOGIN` |
| `POST /api/portal/auth/loginV2` | 新增 App 加密登录，允许未登录，仅接收加密信封，对应 `PORTAL_LOGIN` |
| `POST /api/base/demo/crypto/roundtrip` | 要求登录及演示权限，仅接受 Demo 用途，解密测试文本并返回 |

执行顺序：

1. 客户端获取可缓存的公钥，每次提交前调用准备接口读取当前策略；不要把防重放开关随公钥长期缓存。
2. 关闭防重放时返回 `replayEnabled=false`、`challengeId=null`、`expiresAt=null`，直接进行加密提交和后台解密校验，不访问挑战 Redis。开启时使用密码学安全随机数生成 32 字节挑战 ID，Redis 保存，默认有效期 120 秒，返回 `replayEnabled=true`、`challengeId`、`kid`、`expiresAt`。
3. 挑战记录绑定用途、协议版本、密钥、目标接口；登录后申请的 Demo 挑战还绑定当前用户。有效期以服务端与 Redis 为准，不依赖客户端时间。
4. 客户端生成新 AES 密钥、IV，构造 AAD 并加密正文，向对应业务接口提交信封。
5. 后台限制请求大小、校验格式和用途；开启防重放时必须读取挑战并核对绑定，缺少挑战直接拒绝。两种模式都要解开 AES 密钥、验证 GCM 标签、解析并校验业务字段。关闭模式要求信封中的 `challengeId=null`，旧模式请求提示重新准备。
6. 开启防重放时，在执行业务前原子消费挑战，比较消费到的记录与预期绑定一致。并发提交同一挑战仅一个请求可以继续，其余拒绝；不能使用普通 `get` 后 `delete` 实现消费。关闭时跳过挑战流程，校验成功后进入业务处理。
7. 开启防重放时，解密且结构校验通过的请求一旦消费，密码错误等业务失败同样不恢复挑战。重试需新挑战、新密钥重新加密。

- 多实例共用密钥配置；开启防重放时共用 Redis，挑战 Redis 不可用则拒绝请求，不退回进程内缓存或明文。关闭防重放只移除挑战流程的 Redis 依赖，不移除现有登录/会话自身的 Redis 依赖。
- 明确错误类型：挑战过期/已用、协议或密钥不支持、信封无效、请求过大、频率超限；密钥解包和认证标签失败统一为信封无效，不暴露算法内部错误。
- 登录与受保护业务请求不自动重试。网络超时不能断言业务失败；Demo 重放按钮有意复用保存的原始信封。
- 一次性挑战限制请求执行次数，不提供数据库事务的“恰好一次”；本期接入登录与无副作用 Demo，未来接入支付等写操作需另行设计业务幂等。

## 5. Web / App Demo

- Web 放在 `frontend/apps/admin/features/fa-admin-demo-pages/pages/admin/demo/crypto/`，通过现有 Demo 菜单进入。
- App 放在 `mobile-x/features/fa-demo-mobile/pages/basic/crypto/`，增加首页入口及 `feature.json` 页面声明，使用现有生成流程更新路由。
- 页面优先复用现有布局、输入框、按钮、卡片、JSON 展示和主题；App 使用现有共享组件及触摸事件约定。
- 提供测试文本输入、获取公钥/准备信息、加密、提交后台解密；展示后端当前防重放状态、密钥标识、挑战到期时间（开启时）、信封、解密结果及错误说明。
- 提供“原样重放”“篡改密文”“过期后提交”演示；关闭防重放时说明重放可以成功、过期演示不可用。并发重放、跨用途由定向测试补充，避免页面增加复杂测试控制台。页面只展示后端策略，不提供客户端自行关闭防重放的按钮。
- 相同文本再次加密应得到不同密文，但后台都能还原原文；包含中文、Emoji、换行和空文本的文本字段均能往返。
- 仅使用普通测试文本，明确提示不输入真实密码。Demo 解密接口始终要求当前用户有演示权限，仅开放固定用途和有上限的文本结构；开启防重放时挑战额外绑定申请用户，不能作为任意密文解密接口。
- Demo 正文的 UTF-8 JSON 总大小默认上限 4 KiB（包含字段名、引号和转义）；加密信封字段在 Base64 解码和 RSA 运算前校验长度，避免超大输入消耗资源。
- 菜单使用 `fa-demo` 现有版本 SQL，提供 MySQL、PostgreSQL 两份；不新增业务表。其他部署方言按实际适用范围核对，不错误复用另一方言。

## 6. 登录接入、兼容与运行配置

- 保留 `/api/base/admin/auth/login`、`/api/portal/auth/login` 的原明文请求、成功响应及行为，暂不关闭、不增加强制加密要求。
- 分别新增 `/api/base/admin/auth/loginV2`、`/api/portal/auth/loginV2`，仅接受统一加密信封；成功响应与对应原接口一致，解密后复用原 `AuthBiz`、用户校验、会话和设备信任逻辑，不复制认证规则。
- 本期只切换管理端、mobile-x 的登录 service，页面尽量不动；登录提交前读取准备信息，按服务端策略决定是否使用挑战，不在每次按键时申请。Portal 网页、Desktop 及已安装旧版 App 仍可调用原接口，无需为本次新增接口强制升级。
- 先发布支持新旧接口的后台，再发布已切换的管理端、App；新客户端失败时不自动回退旧明文接口，避免悄悄绕过新接口保护。
- 新接口始终要求加密，关闭防重放仍拒绝明文与混入的业务字段；无需新增“强制加密登录”开关。防重放开关仅作用于接入本协议的新接口，原接口保持不变。
- 旧接口下线时间及是否增加禁用开关留待后续明确，本期不擅自停用。保留期间，用户仍可自行调用旧接口修改明文后提交，这是兼容安排的已知边界。
- Token 登录、短信登录、注册、改密不在本期加密范围，不宣称所有认证流程均已完成保护；注册接口已有注册后登录行为仍保留。
- 新增准备接口遵循现有网关/接口频控策略，保留输入与长度校验；本期不额外建设登录限流平台或全局请求加密拦截器。
- 新增能力通过 `fa.security.crypto.enabled` 启用，本项目默认 `true`；`dev` 使用内置公开测试密钥，仅供假数据演示。生产私钥通过环境变量指定的外置受限文件加载，默认路径为 `${user.home}/.config/fa-admin/request-crypto.pem`，不写入 Git、前端环境变量、App 或响应；生产缺少有效配置时启动校验失败，不回退到开发密钥，也不临时生成各实例不同的密钥。未准备生产密钥时可设置 `FA_CRYPTO_ENABLED=false` 关闭。
- 使用当前活动 `kid` 加密；开启防重放时，轮换需等旧挑战有效期结束再停用旧密钥；关闭时，有效旧密文在旧密钥停用前可能持续重放，不承诺过期保护。各实例同步更新，开发样例密钥只用于测试。
- 复核操作日志、异常日志和遥测：不记录密码明文、解密后的完整登录对象、AES 密钥、私钥、Token、完整设备信任凭据；信封不作为常规日志内容。
- Web Crypto 需要安全上下文；本地可用 localhost，真机联调使用有效 HTTPS，不通过远程 HTTP 加明文回退绕过限制。

## 7. 验证与交付

自动验证采用最小受影响范围：

- Java 定向测试：往返、畸形信封、标签篡改、附加明文不能覆盖解密值、字段超限、用途绑定、新接口拒绝明文；开关关闭时不创建挑战且允许有效密文重放；开启时覆盖缺失/过期挑战、重复及并发消费、用户绑定、挑战 Redis 异常拒绝；客户端伪造关闭状态不能绕过服务端策略。两种配置下，原接口的明文请求与响应行为均保持不变。
- 使用只含测试密钥和虚构数据的跨端样例，验证 Web / Android / iOS 生成的密文均可由 Java 解密；随机加密不通过“输出密文必须相等”判断兼容。
- 验证新旧登录接口的账号、密码和既有会话返回行为；覆盖设备信任保存、短信登录与 Token 登录的必要回归，以及许可异常下公钥、登录准备和新登录接口的可达性。
- 对受影响 Web 文件执行类型检查或定向检查；App 执行相关路由检查并使用项目匹配的 HBuilderV 编译器定向编译 Android / iOS。未验证的平台单独记录，不用静态检查替代原生运行结论。
- 不默认执行完整前端构建、全量测试或浏览器截图验证。

人工验收步骤：

1. 在 Web Demo 输入中文、Emoji 等文本，加密后后台还原；相同文本重新加密得到不同密文。
2. 在 Android、iOS Demo 执行相同流程，后台均能解密，页面主题、状态和错误提示正常。
3. 先配置关闭防重放，确认页面显示关闭、请求不需要挑战、原样重放可成功；再配置开启，重新准备请求，原样重放及挑战过期后提交均拒绝。
4. 两种开关状态下均篡改密文、在信封外追加 `password`、换用途或将登录信封提交给 Demo，确认拒绝且不泄露真实登录信息。
5. 管理端、App 通过新接口正常登录，错误密码及重新提交表现正确，App 设备信任功能正常；Portal 网页、Desktop 和旧版 App 通过原接口继续正常登录。
6. 分别在防重放关闭/开启时，向两个新登录 URL 提交明文，确认均拒绝；原登录 URL 仍接受既有明文请求。管理端、App 正常使用新接口时，F12 中不出现可直接编辑后生效的账号密码字段。

开发完成且自动验证通过后，有人工验收要求的条目标记 `🔍验证中`；用户确认“验证成功”后改为 `✅已完成`。功能 1–5、7–10 已验收，功能 6 仍为后续版本规划。
