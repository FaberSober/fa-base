## 2. 已确认的设计约定

### 2.1 存储与目录

- 每次执行对应一个文件，按执行记录 ID 隔离，同一任务并发执行互不影响。
- 不新增 `base_job_log_detail`，不调用 `FileBizBiz`、`FileSaveBiz`，不写附件表或文件登记表。
- 默认根目录为 `./log/job`，支持配置到生产持久化目录；目录规则如下：

```text
{日志根目录}/{yyyy}/{MM}/{dd}/{jobId}/{jobLogId}.log

示例：./log/job/2026/10/30/12/8651.log
```

- 日期按系统统一时区下的执行开始时间确定；长任务跨天仍写同一个文件。
- 路径使用任务 ID 和执行记录 ID，任务改名不影响历史日志。
- 本期按单实例或共享日志目录部署；多实例各自使用本地磁盘时，需补充第 11 项后才能跨节点查看。

### 2.2 最小数据库变更

| 表 | 字段 | 类型及默认值 | 用途 |
| --- | --- | --- | --- |
| `base_job` | `detail_log_enabled` | Boolean，默认 false | 是否为后续执行记录详细日志 |
| `base_job_log` | `log_path` | `varchar(255)`，可空 | 本次执行的日志相对路径，如 `2026/10/30/12/8651.log` |

- 每次执行开始时确定是否记录日志，修改任务开关不改变已经开始的执行。
- `log_path` 为空表示该次没有登记详细日志，兼容历史记录；非空但文件不存在时提示“日志已清理或不可用”。
- 文件路径由后端生成，不保存服务器绝对目录；读取和删除时校验解析结果仍在配置根目录内。
- 数据库继续保存起止时间、结果、耗时和有长度限制的错误摘要，完整异常堆栈写入文件。
- MySQL、PostgreSQL 分别增加升级脚本，版本按实施时的最新编号递增，并验证真实 SQL 文件头解析；不修改已发布基线。

### 2.3 查看接口与轮询协议

- 在 `JobLogController` / `JobLogBiz` 中增加日志读取和下载能力，前端通过执行记录 ID 请求，后端完成权限校验及文件定位。
- 读取参数包含字节游标和有上限的单次读取量；返回新增文本、`nextOffset`、执行状态、`hasMore` 及文件可用情况。
- 处理 UTF-8 字符边界，游标以服务端返回值为准，允许长行分批读取，避免乱码、重复或漏读。
- 后端先获取执行状态，再读取本批日志并判断剩余内容；只有取得终态后的读取已到文件末尾，前端才停止刷新。
- 高频日志读取、相关状态查询和下载跳过整条 API 日志入库，包括请求参数与响应正文。

## 3. 各功能开发说明

### 3.1 日志开关与数据兼容

- 在任务编辑弹窗增加“记录详细日志”，默认关闭，支持新增、编辑、回显。
- 同步任务实体、执行记录实体、管理端类型及双库升级脚本；历史任务保持关闭。

### 3.2 文件日志与首屏查看

- 新增统一文件日志服务，在 `BaseJob` 开始执行时绑定本次执行上下文，按开关创建文件，统一记录开始、结束及异常堆栈。
- 任务结束时先写完、刷新并关闭日志，再发布成功或失败状态；在 `finally` 清理上下文及文件资源。日志设施故障记录到系统日志，避免覆盖业务异常或改变业务执行结果。
- 执行记录列表增加“查看日志”，未登记日志路径时禁用并提示；抽屉展示状态和日志，支持自动滚动、暂停跟随及文件不可用提示。
- 第一版读取接口上线时即落实第 3 项，避免开发和联调期间将日志正文重复写入数据库。

### 3.3 查看 API 不记录请求日志

- 复用现有 `FaNoLog: 1` 机制，日志查看、增量轮询、相关状态查询及下载均不产生 API 日志记录。
- 下载在响应正文缓存包装前识别并采用流式输出；仅设置 `FaNoLog` 不能解决完整文件仍被缓存的问题。
- 保留正常的认证、权限检查、必要请求校验和上下文清理，仅调整这些接口的请求日志及正文缓存处理。

### 3.4 增量刷新与结束自动停止

- 抽屉打开时立即读取；执行中每轮请求完成后等待 2 秒再查，避免请求重叠，执行状态随日志读取接口一并返回。
- 成功或失败且 `hasMore=false` 时停止；已结束但仍有未读内容时继续分批补齐，确保最后的结束信息和异常不会遗漏。
- 执行中暂时没有新日志时继续轮询，不据此判断任务结束；已结束记录首次打开时读完即停。
- 关闭抽屉、切换执行记录或离开页面时取消定时器及请求，忽略旧请求的迟到响应；确定文件不可用或请求失败时暂停并提供提示与重试入口。
- 暂停跟随仅暂停自动滚动；前端设置有界展示缓冲，完整日志通过下载获取，避免浏览器无限累积正文。

### 3.5 日志下载

- 抽屉提供下载入口，按执行记录 ID 访问，通过流式传输获取当前文件内容。
- 下载不写 API 日志、不缓存完整文件正文；文件不存在时返回明确提示，不影响执行摘要查看。

### 3.6 业务步骤与进度日志

- 提供 `JobRunLogger.info/warn/error` 等统一工具，任务和调用的业务方法记录阶段、批次进度及结果；开关关闭或无执行上下文时不写任务文件。
- 优先使用 `JobDemo1` 展示接入，再按需要为指定业务任务补充关键步骤，不默认采集所有现有 `log.info()` 输出。
- 采用有界缓冲和适当刷新，同次执行的并发写入保持完整；子线程显式捕获、恢复并清理上下文，父任务等待其结束后再完成日志收尾。

### 3.7 文件容量与保留期限

- 在 `FaSetting` 增加任务日志配置：根目录、保留天数、单次文件大小上限；初始建议保留 30 天、单次上限 100 MiB，可按部署容量调整。
- 达到单次大小上限后写入一次截断提示，停止追加正文并预留有界的结束或异常摘要，不影响任务继续执行。
- 定期清理已结束且超过保留期限的文件，再删除空目录；以结束时间判断保留期限，不能按日期目录直接删除跨天运行的文件。
- 文件与执行摘要的保留策略相互独立，本期过期清理以文件为范围，保留执行摘要用于历史查询。

### 3.8 执行记录删除联动

- 单条及批量删除前获取对应路径，成功删除执行记录后清理文件；运行中的记录拒绝删除，避免丢失正在写入的日志。
- 文件不存在时幂等处理；文件删除失败记录系统日志，由后续清理补偿过期的孤立文件，避免因文件故障阻塞摘要删除。

### 3.9 定向验证与人工验收

- 后端使用临时目录定向验证文件隔离、UTF-8 分段读取、收尾顺序、异常、容量上限、过期清理和删除联动。
- 前端使用假时钟验证轮询、终态补齐后停止、关闭与切换取消、迟到响应隔离；请求日志测试确认相关接口不触发日志保存。
- 按受影响文件执行前端 lint / 类型检查、后端目标模块编译与相关测试，并验证双库 SQL 文件头；不默认运行完整前端构建或全量测试。

第 10、11 项作为后续增强单独评估，按实际需求实施。

## 5. 数据量与运行影响

- `base_job_log` 仍是每次执行一条，日志正文不入库，也不逐行更新数据库；附件表与文件登记表没有新增记录。
- 新增存储主要是任务开关和执行记录的相对路径。按每次新增元数据平均 50～100 字节粗估，每天 1000 次执行、30 天共 3 万次，字段数据增量约 1.5～3 MB；不含数据库存储、迁移及备份开销，属于量级估算。
- 查看接口不写 API 日志表，可避免每 2 秒轮询产生每小时约 1800 条请求日志，也避免正文通过响应再次入库。
- 磁盘容量按“开启日志的执行次数 × 平均文件大小 × 保留天数”估算。例如每天 1000 次、每次 1 MB、保留 30 天约 30 GB，应结合保留期限和单次上限管理。
- 查询期间仍有少量执行状态和路径读取，以及增量文件 I/O；日志方案不增加摘要记录数量，但原有摘要表仍随任务执行次数自然增长。

```yaml
fa:
  setting:
    job-log:
      root-path: ./log/job
      retention-days: 30
      max-file-size: 100MB
      cleanup-cron: "0 0 3 * * ?"
```
