## 2. 统计与展示口径

一轮执行指一次实际触发的 `BaseJob` 主流程，以及该流程通过统一执行器关联的全部子任务。手动执行和 Cron 执行采用相同规则，详细日志开关不影响统计。

| 指标 | 口径 |
| --- | --- |
| 最近开始时间 | 最近一轮实际开始执行的时间，不使用计划触发时间或前端点击时间 |
| 最近结束时间 | 与最近开始时间对应同一轮；主流程和全部关联子任务结束后记录，未结束时为空 |
| 最近执行结果 | 最近一轮的执行中、成功、失败或未确认状态；无执行记录时显示“—” |
| 最近总耗时 | 本轮开始至主流程和全部关联子任务结束，包含排队等待 |
| 触发耗时 | 本轮开始至主流程返回或抛出异常；异步子任务结束不决定该值 |
| 累计执行次数 | 实际开始执行的轮次数，包含已结束和未结束执行；一轮只计一次 |
| 成功／失败次数 | 已结束轮次按结果分别累计，任一关联工作出现未被业务处理的异常时，该轮失败 |
| 平均总耗时 | 新口径累计总耗时 ÷ 新口径已结束样本数；成功和失败均参与，未结束记录不参与 |

- 最近开始、结束、结果和耗时必须关联同一条执行记录，不能分别取各字段最大值拼接。较早一轮晚结束时，只更新累计统计，不覆盖较新一轮的摘要。
- 并行子任务的耗时不相加，总耗时按整轮实际经过的时间计算。本期不额外增加独立的“所有轮次最近完成时间”指标。
- 时间沿用系统统一时区；新增耗时以毫秒记录，页面按大小显示毫秒、秒或分秒。无可用值显示“—”，真实 0 毫秒应正常显示。
- 列表默认展示最近执行摘要、最近总耗时、累计次数、失败次数和平均总耗时；触发耗时及成功次数可在详情或提示中查看，避免列过多。
- 将现有调度状态的“运作中”调整为“已启用”，暂停显示“已暂停”；调度启用不代表某轮业务正在执行。
- 沿用列设置、查询和刷新机制；时间、次数列复用服务端排序，导出采用相同统计口径。手动执行接口返回只代表提交调度，页面不推算执行时间。

## 3. 各功能开发说明

### 3.1 最近开始时间展示

- 先完成页面列、前端类型、后端实体、接口返回和增量字段，形成最小可验证功能。
- 在 `BaseJob` 统一入口复用本次执行记录的开始时间，持久化到任务主表；新增、编辑、启停不改变执行时间。
- 字段由后端维护，普通保存、批量操作和旧表单提交均不能覆盖；兼容当前编辑弹窗提交完整记录的方式。

### 3.2 最近执行摘要

- 先打通同步任务的结束时间、结果和毫秒耗时，列表摘要及执行记录详情配套展示；第 3 项再接入异步完成边界。
- 最近一轮开始时清空该轮的结束时间和终态耗时，更新为执行中；主流程返回后单独记录触发耗时。
- 保存最近执行记录 ID 及开始时间，开始、主流程返回和最终结束均按记录归属更新，防止并发执行和迟到更新造成摘要错配。

### 3.3 统一执行器异步跟踪

- `BaseJob` 创建本轮执行上下文；统一执行器仅对带该上下文的直接 `execute(Runnable)` 提交进行跟踪，普通请求的异步工作不计入定时任务统计。
- 提交前登记子任务，包装其开始、异常和结束；向子任务传递本轮上下文，支持它继续通过同一执行器提交关联工作。
- 本轮完成条件为“主流程已经退出，且关联任务全部结束”，并保证只收尾一次；主流程或某个子任务异常后，仍需等待其他已提交工作结束。
- 主流程退出后清理、恢复调度线程上下文，不阻塞等待子任务；工作线程结束时也恢复原上下文，兼容文档中的用户信息传递及调用线程执行的情况。
- 详细日志上下文随执行传播；全部关联工作结束后，先刷新关闭日志，再发布执行终态，沿用原有轮询到 EOF 后停止、运行中禁止删除的规则。
- 保持线程池 Bean 名、配置、生命周期和已有拒绝策略的兼容；拒绝、取消及关闭时未执行的任务必须回收登记，避免正常收尾路径永久等待。保留原有异常传播行为。
- `fa-core` 只提供通用跟踪上下文和执行回调，统计入库及日志收尾放在 `fa-base`，避免反向依赖。

自动覆盖范围限定为本轮通过统一执行器直接提交的 Runnable 及其关联提交。自建线程、其他线程池和公共线程池不自动纳入；被业务捕获且未向外报告的错误不自动判失败。Future 等封装可能在内部保存异常，不能仅根据外层 Runnable 正常返回判断业务成功，相关完整接入属于第 8 项。

检测到未支持的封装时，记录口径为 2、结果为 8（未确认），真实业务结束时间和总耗时留空，不累计成功、失败及耗时样本；保留触发信息和说明。该保护不等同于已实现第 8 项的完整完成协议。

### 3.4 累计执行统计

已实现字段按下表分组，具体命名以实体和 1.0.53 升级脚本为准。

| 存储位置 | 字段用途 |
| --- | --- |
| `base_job` 最近摘要 | 最近执行记录 ID、开始时间、结束时间、结果、总耗时、触发耗时及统计口径标识 |
| `base_job` 累计统计 | 执行次数、成功次数、失败次数、新口径累计总耗时、耗时样本数及新口径统计起始时间 |
| `base_job_log` 执行明细 | 新增主流程返回时间、触发耗时毫秒值、总耗时毫秒值及统计口径版本；保留原有字段 |

- 开始时登记执行记录并原子增加执行次数；子线程只维护本轮跟踪状态，不逐线程增加执行次数或逐日志行写统计。
- 结束时通过执行记录的条件终态更新保证幂等；终态登记与成功／失败次数、总耗时、样本数更新使用同一事务，重复回调不重复累计。
- 累计更新使用数据库原子累加，禁止读出旧值后覆盖；最近摘要的更新与累计更新分别判断，允许旧轮次结束时只累计自身结果。
- 平均值由累计耗时及样本数计算，样本数为 0 时返回空值；不反复累加或平均已有平均值。统计写入错误单独记录，不通过重新执行业务补偿统计。
- 数据保存在任务主表，列表不逐条查询或实时聚合完整日志；删除执行记录、清理文件不扣减累计值，服务重启后已持久化统计仍保留。

### 3.5 历史回填与升级兼容

- 随各阶段配套提供 MySQL、PostgreSQL 增量脚本，版本按实施时最新编号递增；不修改已发布基线或升级脚本。真实文件头解析及版本唯一性必须验证。
- 从现存执行日志回填已知执行次数、历史成功／失败次数，并按最新开始时间和记录 ID 选择同一轮摘要。已删除的历史无法恢复，界面说明累计统计以升级时保留的记录为初始化基础。
- 历史摘要及成功／失败结果标记为旧口径：过去的结束或成功可能只代表入口返回，无法追溯异步业务是否真正完成。不能将旧记录伪装成已经完整跟踪的新记录。
- 平均总耗时只统计升级后按新生命周期完整跟踪的终态记录，使用独立样本数和统计起始时间；不直接以含历史回填的成功／失败总数作分母。
- 原 `duration` 保持秒单位，历史明细继续按原值展示；新记录另存毫秒总耗时，并按需换算回原秒字段。旧记录没有可靠的新口径耗时、触发耗时时显示“—”，不补造精度。
- 未结束历史记录不计入耗时样本；本期不通过次数差或运行时长猜测其仍在运行，也不自动改成成功或失败。重启中断识别沿用第 9 项后续规划。

## 6. 验证与人工验收

自动验证重点覆盖同步、异步、嵌套提交、并发轮次、异常、重复收尾、提交拒绝、CallerRunsPolicy、取消和线程复用；同时回归无定时任务上下文时的线程池行为、异步日志末尾完整性、删除限制及双库迁移文件头。

人工验收在测试环境执行：

1. 新增任务，确认未执行时最近信息和平均耗时显示“—”、次数为 0；分别通过手动和 Cron 执行，核对实际开始时间。
2. 执行同步成功、失败任务，核对同一轮的起止时间、结果、最近耗时和次数；关闭详细日志后重复，确认统计仍正常。
3. 执行通过统一 executor 提交的耗时任务，确认主流程返回后触发耗时已记录，本轮仍未结束；异步业务完成后才更新结束时间和总耗时。
4. 执行多个并行、嵌套子任务及子任务抛异常的情况，确认一轮只计一次，任一未处理异常使该轮失败，总耗时不按线程相加。
5. 让较早一轮晚于较新一轮结束，确认最近摘要仍属于较新一轮，两轮均正确累计；提交旧编辑表单及启停操作，确认不能覆盖执行字段。
6. 查看异步详细日志，确认主流程返回后仍可读取后续内容；结束日志完整、终态后轮询停止，尚有子任务时不能删除执行记录。
7. 以已知样本核对平均总耗时、成功／失败次数及统计起始说明；确认历史旧口径数据不混入新耗时平均值。
8. 升级带历史日志的数据，检查回填及旧口径标识；删除已结束日志、清理文件并重启后，确认已保存的最近摘要和累计统计仍保留。

开发完成的功能标记为 `🔍验证中`，提交对应人工验收步骤；用户确认“验证成功”后更新为 `✅已完成`。尚未开发及后续版本功能保持 `❌未完成`，不能因计划文档已创建而标记业务开发完成。
