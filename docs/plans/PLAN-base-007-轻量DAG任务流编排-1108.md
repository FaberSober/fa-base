## 2. 首版范围与约定

- 复用现有页面 `/admin/system/base/job`，新增类型筛选及流程编排、执行详情入口，不另建独立的任务配置体系。
- 流程节点直接引用后台通过 `@FaJob` 注册的 Java 任务类，以 `clazzPath`（完整包名＋类名）标识实现；不要求在 `base_job` 新建节点任务记录，不支持引用流程任务。一个注册类可被多个流程及同一流程内的多个节点重复引用。任务列表仅需保存流程任务本身，普通任务配置作为独立 Cron 的可选入口继续保留。
- 每个节点具有独立节点 ID，不能用任务类路径代替节点 ID；依赖只在同一轮流程内生效。
- 所有上游节点成功后，下游才可执行；无上游节点作为入口并行启动。允许多个入口和出口，不需要虚拟开始、结束节点。
- 首版按单个编排执行实例设计；部署时须保证只有一个实例承担编排调度和故障扫描。多实例业务执行和接管不在本期范围。
- 首版不新增业务参数传递协议，沿用现有 `BaseJob.run()` 方式；画布中的节点配置仅包含本期支持的编排配置。
- 完整重新执行创建新一轮记录并重跑全部节点；不自动回滚已产生的业务影响。失败处继续和自动重试另行实施。

## 3. 数据设计：新增 2 张表，扩展 2 张现有表

- 本 PLAN 在发布前统一维护 **1.0.54**：MySQL、PostgreSQL 各一份完整脚本，不按字段或功能阶段拆分新升级版本。两个文件是同一逻辑升级的方言实现。
- 本次已集中纳入任务类型/定义、定义历史版本及运行关联、执行日志类型/来源/类名与名称、节点运行表及唯一约束与恢复扫描索引；后续功能实现沿用这些结构，不代表执行引擎已开发完成。
- 节点运行字段确定为 `flow_log_id`、`node_id`、`clazz_path`、`node_name`、`attempt`、`job_log_id`、`status`、`begin_time`、`end_time`、`reason`、`crt_time`、`upd_time`。状态编码为 0等待依赖/10待调度/20启动中/30执行中/40成功/50失败/60阻断/70停止/80未确认。
- 已实际应用的版本不会因修改文件自动补跑；若测试库已执行早期 1.0.54，需核对实际结构后处理缺失部分，不能仅删除升级记录强行重跑。正式发布后该脚本冻结，后续需求变化按正常增量迁移规则处理。

### 3.1 扩展 `base_job`

| 建议字段 | 用途 |
| --- | --- |
| `job_type` | 普通任务 / 流程任务；历史记录默认普通任务 |
| `flow_definition` | 当前可编辑流程定义 JSON；普通任务为空 |
| `current_definition_version_id` | 当前定义版本 ID，普通任务及尚未接入版本的旧流程可空 |

- 复用名称、说明、Cron、调度启停、日志开关及现有最近摘要、累计统计字段。
- 普通任务校验业务类路径，流程任务校验编排定义并使用统一流程执行入口；已有类路径非空约束、任务类选择及空闲任务查询按类型调整。
- 类型在创建后不允许直接切换，避免历史记录及引用语义变化。
- JSON 包含 `schemaVersion`、流程并发上限、节点列表、依赖边及画布位置。节点包含稳定节点 ID、引用任务类路径、显示名称；不包含运行状态。
- 首版 JSON 可使用适配双库的大文本字段存储，由应用统一解析校验，不依赖数据库专属 JSON 查询语法。限制节点数量、边数量和定义大小。
- 普通保存接口不能绕过流程校验或写入服务端统计；前端编辑只提交可编辑字段。

### 3.2 扩展 `base_job_log`

| 建议字段 | 用途 |
| --- | --- |
| `job_type` | 本次执行的任务类型快照，历史记录默认普通任务 |
| `trigger_source` | 手动、Cron、流程节点；旧记录无法确认来源时保留历史标记 |
| `definition_version_id` | 本轮不可变定义版本 ID，普通任务为空 |
| `clazz_path` / `job_name` | 实际执行类和任务名称快照，历史记录可空 |

- 使用不可变定义版本复用，替代逐轮保存完整 JSON；移除 `flow_snapshot` 与压缩草稿。测试阶段不迁移旧快照，补丁清理未关联版本的旧流程运行记录。
- 每轮流程在本表创建一条整体执行记录，每个真正启动的普通节点仍创建业务执行记录；补充任务类快照，无独立配置时任务配置 ID 可空，不为日志关联反向新建任务配置。
- 快照冻结 DAG、名称、引用任务类及执行所需配置；运行中编辑流程或普通任务，仅影响后续新执行。快照不重复保存密钥等敏感内容。
- 节点与其业务执行日志的关联由新增表统一保存，支持从节点查看日志及从业务日志定位所属流程；避免重复维护多套关联字段。
- 流程运行期间停止调度、编辑配置，不影响已冻结的运行记录；配置删除另行执行运行与引用保护。
- 流程整体状态需区分成功、失败、停止、未确认；普通任务保留现有状态含义。新增状态同步前后端枚举、筛选、轮询终止及删除判断。

### 3.3 新增 `base_job_flow_node_run`

| 字段分组 | 用途 |
| --- | --- |
| 归属 | 主键、流程执行记录 ID、节点 ID、引用任务类路径 |
| 历史与关联 | 节点名称快照、尝试序号、普通任务执行记录 ID |
| 调度状态 | 等待依赖、待调度、启动中、执行中、成功、失败、阻断、停止、未确认 |

- 唯一约束采用“流程执行记录 ID＋节点 ID＋尝试序号”；业务执行日志关联建立唯一性约束，按流程归属、状态等必要条件建立索引。

### 3.4 新增 `base_job_definition_version`

- 字段：`id`、`job_id`、`version_no`、`job_name`、`detail_log_enabled`、`flow_definition`、`content_hash`、`crt_time`、`crt_user`、`crt_name`、`crt_host`。整型关联字段与既有配置/日志 ID 类型保持一致。
- 唯一约束为 `job_id + version_no`；版本号从 1 递增。内容哈希由应用对规范化定义、名称和日志开关计算 SHA-256，保留节点/边数组顺序；当前内容未变化不新增版本，回滚旧内容创建新版本。
- 版本为不可变记录，不设置逻辑删除和更新时间。应用在配置行锁及事务内创建版本、更新当前版本关联；运行启动冻结版本 ID，按历史版本回放，不能回退读当前配置。
- 被配置或运行日志引用的版本不得删除；SQL 不加物理外键，沿用应用约束。关联字段提供索引，以支持查引用与清理保护。
- 本轮按用户授权继续修改完整 `1.0.54` 双库脚本；已执行旧版完整 `1.0.54` 的库使用 `docs/sql/{mysql|postgre}/1.0.54_patch_job_definition_version.sql` 手动补丁，增加版本表、关联列和索引，并清理未关联版本的旧流程运行及其节点/业务日志后删去旧快照列；不重复原升级、不改升级记录。执行前停止应用并确认任务均已结束，执行后仅启动新代码。
- 应用保存生成不可变版本，未变化复用当前版本；执行推进和详情仅按日志版本 ID 读取，禁止回退读当前配置。重启仍只标记未确认、不重跑节点。不支持旧快照兼容；用户已确认本轮验证通过，功能 3b、3c 标记为 ✅已完成。
- 验证步骤：停应用后执行对应补丁；启动新代码并保存已有流程；重复执行确认版本复用；修改并保存后确认生成新版本且历史运行图不变；确认普通独立任务日志保留。

## 4. 各功能开发说明

### 4.1 类型管理与流程编辑（功能 1–2）

- 列表新增类型展示和筛选；普通任务保留原编辑方式，流程任务提供编排入口。通用保存、导入等写入路径统一校验。
- 提供添加普通任务节点、拖动、连线、删除、自动布局和保存；优先核查仓库已有图编辑能力，确需新增依赖时评估兼容及体积。
- 后端校验非空流程、节点 ID 唯一、引用类已注册且可作为普通 Java 任务执行、连线端点有效、无自环、无重复边、无循环依赖及配置上限；前端同步提供即时提示。
- 选择节点无需创建独立任务配置；若同一类另有普通任务 Cron 配置，其暂停仅停止独立调度，不阻止流程调用。页面提示两者相互独立及可能并发执行的边界。

### 4.2 执行入口与依赖推进（功能 3–4）

- 手动和 Cron 采用同一流程启动入口；事务内创建整体日志、关联定义版本和全部节点记录，初始化完成后才提交执行。
- 基于现有任务入口提炼可复用的执行生命周期，显式传递本轮流程与节点归属。业务任务保持 `run()` 调用方式，不要求修改业务代码。
- 节点调用不能只提交一次无关联的 Quartz 触发；必须绑定具体普通任务执行记录，用该记录的真实终态驱动依赖。
- 复用统一执行器的异步跟踪，主方法返回不视为节点成功；关联异步全部完成后才判定成功或失败。未确认结果阻断下游，不按成功放行。
- 满足依赖的节点按稳定顺序领取，受流程并发上限约束；启动中、执行中及尚有实际工作未确认结束的节点占用并发容量。
- 同一流程内引用同一普通任务的多个节点默认串行执行，避免隐式重入；不同流程或独立调度之间的任务级互斥不作自动保证，页面说明该边界。
- 失败节点的依赖后代标记阻断，无依赖关系的其他分支继续执行。已启动工作收尾后再汇总流程结果：存在未确认优先显示未确认，否则失败优先于主动停止，全部成功才成功。

### 4.3 运行图、日志与统计（功能 5）

- 详情使用运行快照绘图，显示节点状态、时间、耗时和阻断原因；点击已启动节点进入现有业务日志，未启动节点不生成虚假业务日志。
- 流程整体日志记录开始、节点调度、结果及停止等编排事件；业务正文仍写节点自己的文件，避免不同节点日志上下文串写。
- 流程开始及结束各维护一次整体统计，节点执行维护本轮节点统计；无独立任务配置时不创建普通任务配置或累计其配置统计；累计次数不按节点数量增加到流程上。
- 流程总耗时为整轮开始至最终收尾的经过时间，包含依赖等待与排队，不累加并行节点耗时；触发耗时仅表示入口初始化返回时间。
- 已确认成功、失败流程参与现有平均耗时；主动停止和未确认不计成功、失败及平均样本。未确认不伪造真实业务结束时间。
- 查看页面沿用现有请求和轮询机制，覆盖新增状态；整个流程收尾后才结束整体日志和统计。

### 4.4 调度、重叠与停止（功能 6）

- Cron、立即执行、启动恢复按类型路由；保留普通任务当前行为。
- 同一流程不允许重叠运行，使用可恢复的服务端互斥控制，而非仅前端按钮防重。定时重叠触发跳过并记录原因；手动触发明确提示，不计为实际执行次数。
- 停止调度只影响未来触发；停止本轮通过持久化状态禁止领取新节点，不强制中断现有 Java 业务线程。停止与节点领取需原子协调。
- 停止后等待已启动节点结束再确认整轮停止；存在无法确认的工作则保持未确认。完整重新执行需等上一轮不再有活动工作，并创建新记录。

### 4.5 一致性、恢复与保护（功能 7）

- 状态转换使用事务及条件更新，重复回调、并发汇合、重复请求均不得重复启动节点或重复累计统计；终态更新后再推进下游。
- 完成回调负责及时推进，数据库持久状态扫描负责补偿，防止回调丢失或短暂数据库失败造成永久等待。编排动作在业务事务提交后执行。
- 为“已领取但尚未启动”“已启动但关联登记失败”等窗口设计可核对状态；无法确认业务是否已启动时标记未确认，不盲目重新执行业务。
- 单实例服务重启后核查遗留执行，无法确认已运行工作的结果时记录中断原因并转未确认、阻断后续；不自动重跑可能已产生副作用的节点，也不因页面终态就断言远程副作用已经停止。
- 未确认的活动执行需经有权限的人工核查后才能解除运行互斥；记录操作者、原因及处理结果，不允许将未确认直接伪造为业务成功。
- 删除独立普通任务配置不影响按类路径引用的流程；执行类卸载或变更时校验注册可用性，启动前再次校验并冻结类路径，删除流程时检查活动执行。删除执行日志及清理策略需保护活动流程、节点关联和历史定位能力，避免孤立记录。
- 复用现有权限体系，对编辑、执行、停止、解除互斥及日志访问做服务端校验；不能仅通过前端隐藏按钮控制权限。
