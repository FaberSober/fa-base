## 三、各功能开发说明

### 01 页面骨架与入口
- 页面：在 `frontend/apps/admin/features/fa-admin-pages/pages/admin/system/base/job/` 下新增 React 页面，按现有页面发现与菜单约定接入 `/admin/system/base/job/visual`；左侧 300px 固定、右侧自适应；列表页工具栏加入口
- 菜单：按项目菜单和版本升级规则同时提供 MySQL、PostgreSQL 脚本；模拟数据集中存放并标注 MOCK，由 03–05、08–09 分步接入真实数据替换
- 后台：无
- 测试：能从菜单和列表页进入；左右布局、明暗主题下正常；模拟数据能显示

### 02 执行日志表确认与补齐
- 后台：复用 `base_job_log` / `JobLog`，已有任务 ID、名称、类型、`beginTime`、`endTime`、状态、触发来源、错误信息及毫秒耗时；`BaseJob` 已登记执行记录，先核实普通任务、任务流及节点覆盖，避免重复记录
- 后台：已有 `(job_id, begin_time, id)` 索引；按日期及跨天查询的实际执行计划检查是否需要 `begin_time` 索引，必要时提供 MySQL、PostgreSQL 双份版本升级 SQL
- 后台：核实摘要记录与文件日志各自的清理策略；旧记录可能缺少快照或精确耗时，页面需兼容
- 核查结果：普通任务、流程整体和已启动节点均有记录；普通任务现补充名称、类路径和来源。文件日志默认保留 30 天，摘要独立于文件清理，允许按现有规则手动删除。
- 后续性能验证：日期和跨天查询的执行计划及索引需求在 04、08 联调时检查。
- 验收点：手动及 cron 执行、任务流和节点的记录覆盖明确，缺口有针对性测试；历史数据缺失字段不影响展示
- 是否需要人工验证：否

### 03 日历与每日角标
- 页面：月视图，点击选日期，上下月切换；每格圆点绿色为全部成功，红色为有失败
- 后台：`GET /api/base/admin/job/visual/calendar?month=` 返回当月每天的总数、失败数
- 验证说明：用户已验收通过；项目级 TypeScript 检查存在配置及类型解析问题，后续单独处理。
- 测试：切换月份、选日期；有失败的日期显示红点

### 04 时间轴基础展示
- 页面：ECharts `custom` series 画色块；X 轴 0–24 点，Y 轴为当天有执行的任务；成功绿、失败红；一条红色当前时刻线，图例里说明；悬浮显示任务名、开始和结束时间、耗时、结果
- 后台：`GET /api/base/admin/job/visual/timeline?date=` 按任务分组返回当天明细
- 验证说明：用户已验收通过；项目级 TypeScript 检查仍有配置及类型解析问题，后续单独处理。
- 测试：选今天和历史日期，色块位置和时长与数据一致；今天出现红线

### 05 功能按钮、筛选与当日统计
- 页面：回到今天、刷新；类型、结果、名称筛选；统计卡片（总执行、成功、失败、成功率、平均耗时、最长耗时）
- 后台：timeline 接口增加 `type`、`status`、`keyword` 参数，返回 `stats`
- 测试：筛选后时间轴与统计同步变化

### 06 缩放与高频任务聚合
- 当前已实现前端时间窗口切换与滑块；高频任务后台聚合及其验收仍待完成。
- 页面：全天、6 小时、1 小时切换，滑块平移（`dataZoom`）；聚合块透明度表示次数，桶内有失败显示红色
- 后台：窗口内某任务记录超过 40 条时按 15 分钟分桶聚合（SQL `GROUP BY`），否则返回明细
- 测试：「任务流1」「测试任务1」全天为聚合块，放大到 1 小时显示每一次执行

### 07 执行详情抽屉
- 页面：点击色块从右侧打开抽屉，显示结果、起止时间、耗时、触发方式、cron、日志；聚合块提供「放大查看明细」
- 后台：复用 `/api/base/admin/jobLog` 的详情及 `read/{id}` 分段读取；沿用现有 `JobLogDetailDrawer`，按需扩展
- 测试：失败记录能看到错误信息

### 08 运行中与跨天处理
- 页面：运行中色块延伸到当前时刻并闪烁（尊重减少动画设置）
- 后台：按 `JobLogStatusEnum` 区分执行中、停止中和终态，不能仅凭 `endTime` 为空判断运行中；跨天记录在两天都返回，并截断到 00:00–24:00，带 `crossDay` 标记
- 测试：模拟 23:50 开始、次日 00:10 结束的任务，两天都能看到

### 09 未来计划预览
- 页面：蓝色虚线空心块表示计划；今天为红线右侧的计划；未来日期整天为计划；日历显示空心角标；「显示计划」开关；按结果筛选时自动隐藏计划
- 后台：`GET /api/base/admin/job/visual/plan?date=`，用 Quartz `CronExpression.getTimeAfter` 推算；单日超过 2000 次的 cron 只返回按桶计数；预计耗时取最近 20 次成功执行平均值；已暂停任务也推算并标记
- 测试：对照 cron 核对触发点；暂停任务显示计划但有标记

### 10 自动刷新与列表联动
- 页面：自动刷新开关（仅今天有意义，30 秒）；列表页「历史记录」带日期和任务跳转到本页
- 后台：无
- 测试：自动刷新时红线和运行中色块更新；跳转后日期和高亮任务正确

### 11 联调与优化
- 明暗主题颜色、对比度检查
- 单日 1 万条记录以内，切换日期 1 秒内刷新
- 空数据、接口失败、任务数过多（Y 轴滚动）的处理
- 补充必要的接口和页面测试

## 四、接口与前端结构

- 前端沿用 `fa-admin-pages` 的页面、`services/base/admin/job.ts`、`jobLog.ts` 和 `types` 组织方式，通过项目 `BaseApi` 调用；图表复用已安装的 ECharts，日期使用 dayjs，主题沿用项目 token。
- 后端沿用 `JobController` / Biz / Mapper 分层和 `Ret` 响应；查询与聚合放 Biz / Mapper，日期边界和参数校验在服务端处理。
- 时间轴默认展示任务级执行；任务流节点日志的过滤方式须在 02 核实，避免和流程整体重复统计。保留执行中、停止中、成功、失败、已停止及未确认状态，不将所有非成功状态当作失败。
- 日期区间使用半开区间 `[当日零点, 次日零点)`；跨天查询包含与区间相交的记录，运行中按状态及当前时间计算。SQL 聚合须分别兼容 MySQL 和 PostgreSQL。


| 接口 | 作用 |
|---|---|
| `GET /api/base/admin/job/visual/calendar` | 当月每天统计 |
| `GET /api/base/admin/job/visual/timeline` | 当天时间轴与统计 |
| `GET /api/base/admin/job/visual/plan` | 计划触发点 |
| `/api/base/admin/jobLog` 详情及 `GET /api/base/admin/jobLog/read/{id}` | 复用单次详情与分段日志读取 |


## 五、验收标准

1. 切换日期，日历角标、统计、时间轴在 1 秒内刷新
2. 高频任务不卡顿：全天聚合，放大后显示每一次执行
3. 跨天任务在相邻两天都显示，运行中任务延伸到当前时刻
4. 今天显示红色当前时刻线，右侧为计划块；未来日期只有计划块
5. 明暗主题下颜色和对比度可读

## 六、风险

| 风险 | 处理 |
|---|---|
| 旧日志字段缺失或日志被清理 | 兼容缺失字段；已清理记录及文件不可追溯 |
| 超高频任务日志量大、查询慢 | 索引 + SQL 聚合，必要时只保留聚合统计 |
| 时区不一致导致日历与时间轴错位 | 明确服务端时区及接口日期格式；日期边界、cron 推算与前端展示使用同一时区，并覆盖跨时区测试 |
