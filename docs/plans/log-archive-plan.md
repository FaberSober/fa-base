# 日志归档模块改造 PLAN

> 目标：解决日志表持续膨胀导致查询变慢的问题，建立统一的日志归档、查询和保留机制，并兼容 MySQL、PostgreSQL、Oracle 11.2。

## 1. 改造目标

* [x] 支持日志按月自动归档
* [x] 支持历史日志永久保留或按月清理
* [x] 支持跨当前表和归档表查询
* [x] 支持 MySQL、PostgreSQL、Oracle 11.2
* [x] 保证归档任务幂等、多实例安全
* [x] 日志归档和日志清理相互独立
* [x] 抽象为可扩展的通用日志归档能力

## 2. 归档规则

* 当前日志始终写入固定表，例如 `base_log_api`
* 每月 1 日凌晨执行上月日志归档
* 归档表命名格式：

```text
base_log_api_YYYY_MM
```

例如：

```text
base_log_api_2026_08
```

* 归档完成后重新建立新的当前日志表
* 归档过程不得影响正常业务请求

> 实施说明：现有请求日志为同步写入固定表。为避免表重命名期间的写入失败，实际实现采用“创建归档表、幂等复制指定月份数据、校验数据量、按主键分批删除当前表历史数据”的方式；`base_log_api` 始终存在且持续作为当前写入表。

## 3. 系统配置

增加日志生命周期配置：

* [x] 是否开启按月归档
* [x] 日志保留策略

  * `FOREVER`：永久保留
  * `MONTHS`：保留指定月数
* [x] 保留月数配置
* [x] 移除旧版按日志数量自动删除逻辑（现有实现与原 PLAN 的固定三个月描述不一致）

归档和删除必须独立：

```text
归档：控制是否拆分历史日志
清理：控制历史日志保留多久
```

## 4. 归档元数据

新增统一的日志归档记录，用于管理历史归档表。

至少记录：

* [x] 日志类型
* [x] 原始表名
* [x] 归档表名
* [x] 归档月份
* [x] 数据开始时间
* [x] 数据结束时间
* [x] 数据量
* [x] 归档状态
* [x] 归档时间
* [x] 异常信息

建议状态：

```text
PREPARING
ARCHIVING
SUCCESS
FAILED
```

历史日志查询优先读取归档元数据，不通过扫描数据库表获取归档信息。

分别实现：

```text
MySqlLogArchiveDialect

```

负责处理：

* [x] 创建日志表
* [ ] 创建临时/下一周期表

业务层不得直接依赖具体数据库归档 SQL。

## 6. 定时归档任务

新增日志归档调度任务。

执行流程：

```text
获取分布式锁
    ↓
检查归档配置
    ↓
检查目标月份是否已归档
    ↓
准备新日志表
    ↓
归档当前日志表
    ↓
切换新的当前日志表
    ↓
校验结果
    ↓
写入归档记录
    ↓
释放锁
```

要求：

* [x] 支持重复执行
* [x] 已成功归档的月份不得重复归档
* [x] 多实例只能有一个实例执行
* [x] 失败后记录失败状态和原因
* [x] 归档失败不得影响正常业务

## 7. 日志查询改造

根据查询时间范围自动确定查询表。

规则：

```text
当前月份
→ base_log_api

历史月份
→ base_log_api_YYYY_MM

跨月份
→ 当前表 + 对应归档表
```

跨表查询：

* [x] 使用 `UNION ALL`
* [x] 根据归档元数据确定需要查询的表
* [x] 支持统一分页和排序
* [x] 不在 Java 内存中合并完整日志结果

日志页面建议提供：

* 今天
* 最近 7 天
* 本月
* 上月
* 自定义时间

限制单次查询跨度，避免一次扫描大量历史月表。

检查现有日志查询条件并统一优化索引。

重点考虑：

* [x] 创建时间
* [x] 用户 + 创建时间

## 9. 历史日志清理

新增独立的历史归档清理任务。

### `FOREVER`

```text
不删除历史归档表
```

### `MONTHS`

超过配置保留月份后：

```text
DROP TABLE base_log_api_YYYY_MM
```

然后同步更新归档元数据。

要求：

* [x] 不再对超大日志表执行大量历史数据 `DELETE`
* [x] 删除前确认目标表属于归档管理范围
* [x] 清理失败记录异常，不影响其他归档表

## 10. 日志写入稳定性

日志功能不得影响主业务。

* [x] 日志写入异常不得导致业务请求失败
* [x] 保持当前业务写入表名不变
* [ ] 如现有架构允许，可逐步改为异步日志写入
* [ ] 本次不强制引入 MQ 等额外基础设施

## 11. 通用化

归档能力不得只针对 `base_log_api` 写死。

设计为可扩展能力，后续支持：

```text
base_log_api
base_log_login
base_log_oper
其他日志表
```

通过日志类型或配置声明：

* 是否参与归档
* 当前表名
* 归档表名前缀
* 保留策略

统一由日志归档管理模块处理。

* [x] 通过 `LogArchiveTarget` 声明日志类型和当前表名，可复用到其他同结构日志表。
